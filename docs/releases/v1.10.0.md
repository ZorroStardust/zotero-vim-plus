## v1.10.0 — Note Vim editing, precise navigation and macOS input fix

This release brings a much more capable Vim-style editing layer to Zotero's
rich-text notes, alongside a confirmed fix for the macOS input problem in
[issue #6](https://github.com/ZorroStardust/zotero-vim-plus/issues/6).
The changes below cover everything added since v1.9.0.

### New: precise character and bracket navigation

- `f{char}` / `F{char}` find a character forward / backward on the current
  logical line. `t{char}` / `T{char}` stop just before / after it.
- `;` repeats the last character find; `,` repeats in the opposite direction
  without changing the remembered original direction.
- Counts work with these motions: `2fa` finds the second `a`. They also compose
  with editing operators: `dt)` deletes up to `)`, while `df)` includes it.
- `%` jumps between matching parentheses, square brackets and braces, including
  nested pairs across paragraphs. `d%` includes both ends of the pair;
  `50%` jumps to the line halfway through the document.
- A failed character find leaves the note text and caret unchanged.

Pair matching is text-based, not a programming-language parser. Character
finds stay on one logical line; pair matching skips escaped delimiters and
one-line quoted strings.

### New: note search

- `/` searches forward and `?` backward in a compact search bar below the note.
- Live match counts and a highlighted next-match preview help locate text.
- Enter accepts the result and returns focus to the note. Escape or leaving
  the search cancels and restores the original caret or selection.
- `n` / `N` repeat in the remembered direction / its opposite, with wraparound
  and counts such as `3n`. Empty Enter repeats the last query.
- `*` / `#` search the complete word under the caret, including Unicode words.
- Search works with operators and Visual selections: for example, type
  `d/target` and press Enter to delete through a searched motion.

Search is case-sensitive literal text, with support for Chinese and other
Unicode text. Vim regular expressions and search-and-replace are not included
in this release. This is note search, separate from the PDF reader's find bar.

### New: note Visual modes and text objects

- `v` starts characterwise Visual selection; `V` selects logical lines.
- Motions, counts, character finds, pair jumps, searches and text objects can
  extend the selection. `o` swaps its active end.
- `y` copies, `d` / `x` delete, and `c` deletes and enters Insert mode.
- `v` / `V` switch selection types; Escape returns to Normal.
- `gv` restores the last Visual selection only while the note text is unchanged,
  avoiding stale selections after an edit.
- Inner/around objects now cover words and WORDs, sentences, paragraphs,
  single/double/backtick quotes, parentheses, square/curly/angle brackets, and
  literal paired HTML/XML tags.
- Objects compose with `d` / `y` / `c`: try `ci"`, `da(` or `viw` followed by
  `y`. Bracket aliases and outer nested counts such as `2ci(` are supported.

Tag objects operate on tags written as text, not Zotero's formatting markup.
Sentence objects recognize English and Chinese ending punctuation; paragraph
objects use native rich-text blocks. This is not a complete implementation of
Vim's configurable sentence/paragraph rules, syntax parsing or block Visual mode.

### New: compact logical line numbers and command hints

- Absolute line numbers appear in the active note editor by default, with the
  current line highlighted. They match `12G`, `12gg` and `j` / `k`.
- Paragraphs, empty lines and explicit hard breaks count; automatic visual
  wrapping does not add numbers. Tables retain global document numbering with
  a small gutter inside each cell.
- The gutter reuses the existing left margin. Headings with Zotero's H1/H2
  badges place a small, flat number below the badge, avoiding overlap without
  reserving a wide extra column.
- Toggle line numbers in **Settings → Zotero Vim Plus → Modes** without restarting.
- Commands waiting for another key show a small, non-interactive hint at the
  bottom of the editor. `f` asks for a character; `2d3f` shows the sixth
  occurrence. Counts, operators and pending text objects also get hints.
- Hints use English or Chinese according to the plugin/Zotero language setting
  and remain until completion, Escape or leaving the editor.

Line numbers, hints and the search bar are UI-only: they are not inserted into
the saved note or its undo history and are hidden when printing.

### Improved: everyday editing and tab navigation

- Corrected word/WORD motions, first-nonblank positioning with `^` / `I`,
  counted line jumps, and operator/motion counts. `2d3w` operates on six words.
- `o` inserts a clean empty line below; `O` inserts one above. Neither splits
  off the original line's trailing text. In simple lists they create a sibling
  list item.
- `p` / `P` distinguish characterwise and linewise text and support counts.
  Yank, delete and change operations, including `x`, update the internal note
  copy buffer.
- Rich-text edits use native editor transactions, preserving the remaining
  formatting and integrating with Zotero's save and undo flow.
- `Shift+J` / `Shift+K` switch to the previous / next tab in note Normal mode,
  but type uppercase letters in Insert. They do not switch tabs in Visual mode.
- Main-window leader shortcuts remain available in note Normal mode;
  `<space>bj` opens the tab picker.

### Fixed: macOS note command letters being inserted (#6)

The diagnostic reports showed that Vim handled and canceled `keydown`, yet
later `keypress` and cancelable `beforeinput` events still inserted the same
letter. Handling the original event too early at Zotero's main-window boundary
could also keep it from reaching the note iframe listener.

This release lets the original event reach the note editor and guards the
later native character-input events there. Consumed commands remain guarded
even when `i`, `a`, `o` or a change command immediately enters Insert mode.
The guard is cleared by the matching key release, a new key press, loss of
focus or changing editors. Search typing, ordinary Insert input, native IME
composition and Vim's own editing/undo commands retain their intended behavior.

The [reporter confirmed that the fix works in both note tabs and side notes](https://github.com/ZorroStardust/zotero-vim-plus/issues/6#issuecomment-5947724456)
on their macOS system. Thank you to **@n-eagle-eye** for the diagnostic reports
and repeated testing!

Also fixed:

- Turning note Vim off no longer lets Backspace trigger “top level” / parent
  collection navigation while editing a note. Ordinary note input stays native.
- The library's right-side note editor is now recognized separately from the
  PDF reader's Notes sidebar. Standalone note-tab lookup remains authoritative,
  including while a selected note is loading.
- Editor changes and disabling note Vim remove input listeners and clear
  pending state, avoiding duplicate handling or stale consumed keys.

### Installation, compatibility and scope

Download the attached **`zoetero-vim-plus.xpi`**, install it through
**Tools → Plugins → gear menu → Install Plugin From File…**, then restart Zotero.
The plugin supports Zotero **7.0–10.*** on macOS, Linux and Windows.

Automatic-update metadata has been updated for v1.10.0.

Note Vim is enabled by default and operates in library notes, reader-side notes
and note tabs. Click inside the text, press Escape for **NOTE NORMAL**, press
`i` to type, and Escape to return to Normal. It is independent of PDF reader
modes. Disable it under **Settings → Zotero Vim Plus → Modes** to use only
Zotero's native note editor.

This remains a practical Vim-style layer over Zotero, not a full Vim engine.
There is no `:` command line, substitution, Vim configuration file,
named-register system or custom note-command remapping yet.

### Documentation and checks

- Updated English, Chinese and Spanish README descriptions with quick-start
  examples, complete note command tables, logical-line behavior and limitations.
- Added regression coverage for the macOS event sequence, original-vs-forwarded
  event routing, library note detection, native input and listener cleanup.
- The release build runs syntax, manifest, binding-sync and all existing
  regression checks. During development, local browser checks also exercised
  the native rich-text editor: 27 cases across note tabs, reader sidebars and library notes, plus
  14 advanced editing cases. These local checks complement the reporter's
  actual macOS confirmation; they are not an all-platform certification.
